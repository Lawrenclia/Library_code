# 机构知识库工作台

Tauri 2 + Rust + SQLite 桌面工作台。界面使用 shadcn-vue 官方开源组件，来源、MIT 许可和组件下载记录见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。业务规则依据原始 PPT 和 [重构目标](../docs/TAURI_REBUILD_GOAL.md)。

实际验证结果与剩余目标见 [验收记录](../docs/TAURI_VERIFICATION.md)。

## 使用

Windows 安装包生成在 `src-tauri/target/release/bundle/nsis/机构知识库工作台_0.1.0_x64-setup.exe`。

1. 导入实际名单 Excel，选择负责人。已处理与跳过标记会读取，历史进度保留。
2. 打开 WOS / SA / 查本库 / 导入管理工作页，在应用自己的浏览器窗口内完成登录。
3. 点击“检索 / 下载 WOS”，按所选负责人的零匹配任务逐篇检索。普通零结果继续后续论文；浏览器通道故障暂停队列。跳过项有独立入口。
4. 选择论文，在“来源”查看原始 TXT 和身份核验结果；也可以读取已有的单篇 WOS 完整记录 TXT。
5. 在“核验”保存实际查到的来源和结论。零匹配分为本库缺失、纠正题名后已有、非交大、未查询到四条路径。本库缺失和纠正题名后已有必须先使用来源中的正确题名点击“查询本库并保存结果”；已知 DOI、WOS 号一并查询。完整分页和原始字段归入来源，失败不当作零条，有候选时明确选择真实条目 ID，不能默认第一条。只有所有实际查询明确零条且身份、交大归属已核实才允许缺失补充；上传前再次查询。推送后查到实际条目再关联、认领与处理。
6. 需要补充成果时，在“平台操作”分别执行并核验上传、导入、推送、关联和最终 SA 处理。每次写入有本条确认弹窗，结果不明先回读平台。
7. 在“模板与材料”注册真实 Excel 模板；四份现有模板默认第二行表头，其他模板按实际行号设置。原表工作表、样式、公式与格式要求保留。
8. 在“模型与设置”填写 API 地址、模型和密钥。随后在论文的“AI 建议”按已有来源分类、填写模板，导出时列出缺项并保存字段来源。
9. 需要补充学者别名时，在“平台操作”打开学者管理，按完整工号读取学者与已有别名；选择含真实署名的文献来源，再确认保存。本条保存后回读，不改变默认姓名；结果未知时先核验上次结果。
10. 多条匹配任务在“平台操作”打开重复数据管理，按题名读取候选、选择候选组并读取完整字段。明确选择主条目和被合并条目，提供同篇来源与保留差异的说明，再确认合并。每次合并记录前后字段和实际主条目；仍有多条时继续核对，最终回到 SA 处理。结果未知时先回读上次操作，不重新合并。
11. 唯一匹配后在“核验”读取逐项清单，通讯作者、第一作者、交大第一单位、作者认领、DOI/WOS 身份及其他原因分别取证。本库正确时保留该值并保存具体备注；SA 正确时可打开对应条目编辑页，依据原文修改并保存，刷新清单后程序核对实际值。通讯作者和共同第一作者的可见控件也可在工作台保存：打开并登录学者管理，点击“按工号读取可编辑作者字段”，明确选择作者行，填写本项原文来源、依据和备注，再确认保存。程序重新查询完整工号与表单、只修改对应复选框，并回读全部元数据和 SA 后保存本项结论；结果未知时仅用“核验上次本库字段保存结果”回读，不重复保存。署名顺序、其他角色标记及单位顺序目前仍需在实际编辑页处理。作者认领须回读到同一完整工号。每项分别保存来源、依据和备注，不能用总勾选跳过；完成前再次回读，逐项备注一起提交 SA。

下载队列会保存建立时的负责人、范围、顺序、完整名单字段及逐篇结果。暂停或退出后，先恢复 WOS 工作页，再点击“继续原队列”。已经记录的零结果不重新检索，已核验文件复用。恢复前题名、工号、跳过标记或业务状态改变的任务只记录未执行，保留当前任务等待核对；后来新增的行不加入原范围。需要换范围时，先暂停，再点击“结束原范围”并确认；文件和历史结果保留。来源 Excel 的“下载队列结果”工作表包含全部历史范围、原始输入与逐篇结果，长内容分段保留完整哈希。

关联后会自动回读完整实时 SA 并建立逐项清单，原始名单的匹配数仍保留。即使名单为零，实时变为唯一后也必须逐项核对；核验状态由实际记录决定。同一平台号再次关联只回读，已有其他条目不会被覆盖。认领作者必须明确选择，没有默认选中行。关联结果未知时先点击“核验上次 SA 操作结果”，程序按原始载荷确认同一任务与平台号后恢复先前阶段。

任务进度、专用浏览器状态和文件位于 Tauri 的本机应用数据目录，界面“模型与设置”展示真实绝对路径。“打开工作目录”可直接查看：`downloads` 保存浏览器下载，`artifacts` 保存核验归档，`templates` 保存注册模板，`materials` 保存字段来源审计记录。导出的材料与来源报告在保存对话框中选择位置。不会使用系统浏览器的 Downloads 作为自动下载目的地。

任务表支持搜索、负责人筛选、题名 / 匹配数排序和每页 12 项分页；侧栏可收起，主题可切换深色并保存偏好。论文详情右上角“展开”提供全宽阅读与填写区域，“返回列表”保留当前分页、选中论文和未保存的表单内容。统计来自实际任务数据。

同一篇已核验论文可共享原始文件，每条 SA 的负责人、认领和执行历史独立。多个内容不同的核验文件会要求人工选择来源版本。来源报告包含“任务与来源”“原始来源依据”“AI 字段来源”三个工作表；长依据按片段保存，保留完整内容与哈希。较长的 SA、工号、平台编号必须以 Excel 文本保存，避免数字精度损失。

## 名单版本变化

导入名单时，原文件按哈希归档到 `inputs`。同一 SA 的题名、完整工号、标识符、匹配条目或责任人等关键字段变化时，保留原任务并显示“新名单版本待核验”，阻止继续使用旧结论操作。逐字段查看变化，点击“读取新版本与实时 SA”，填写来源与责任人安排、具体依据并明确确认后才可采用。

采用前再次核对全部实时字段；变化或仍有未确认操作时拒绝切换。采用后重新核验业务结论，保留完整旧任务与输入历史；只有原文件重新解析后仍证明同篇，才保留已核验文件和已有导入检查点。历史上传与导入记录跨版本保留，阻止同篇再建批次。来源报告可追溯完整历史。此流程处理当前名单重新导入的变化；旧日志中的历史任务键不同仍需独立处理。

## 旧版数据迁移

当前版上传结果未知时，点击“回读上传 / 导入 / 推送结果”。按原载荷和归档哈希，只读核对原窗口的文件字节、上海交大机构、SA 说明、文件名/大小及服务器业务成功回执，再恢复为上传成功。不会重新上传；表单、回执或文件引用变化时停止。已经确认上传后再次点击回读也检查原窗口，不等待尚未建立的批次。

保留原上传工作页。窗口关闭或重载且未找到可核验批次时继续保留结果未知，不能直接重发。实际同说明批次已存在时，核验单篇题名、DOI/WOS 和阶段后恢复。旧版本缺少原载荷/页面检查点、窗口丢失后的独立恢复仍需人工核对或后续适配。生产安装包没有测试故障注入入口。

先关闭旧版助手，在“模型与设置 → 迁移旧版记录”选择旧代码目录（目录内有 `list.xlsx` 与 `runtime`）。预览名单、进度、导入阶段和版本差异后，点击“迁移这些记录”。原目录保留；完整历史存入新工作台 SQLite，按哈希核验的原始 TXT 复制到 `artifacts`。重复同一快照不会重复建立任务；预览后源数据变化必须重读，有任务冲突时整批任务变更回滚。

支持 `runtime/progress.sqlite3`、`runtime/wos-imports/imports.sqlite3` 和 `runtime/wos-downloads/imports.sqlite3`。名单外的导入日志也保留并阻止同篇创建新批次。旧版已发出的操作以待确认检查点保留，先回读；旧 SA 已结案可用“只读核验旧版 SA 完成记录”核对完整工号、题名、已处理及原备注。旧待认领但未结案、未知上传、旧历史任务键不同的独立冲突处理、其他分类/准备 JSON 和 DPAPI 密钥迁移尚未补齐。密钥和登录目录不读取；可在模型设置中配置当前密钥。此版本已测试模拟数据库与界面，真实目录迁移仍待现场验收。

## 开发

需要 Windows Rust MSVC 工具链、Node.js、pnpm 和 WebView2。

```powershell
cd desktop
pnpm install --frozen-lockfile
pnpm desktop
```

`pnpm build` 检查 Vue 类型并构建前端，`pnpm bundle` 生成 Windows 安装包。`pnpm format` 格式化本项目页面和业务组件，官方组件保留其下载时源码。

核心测试在 `core` 目录运行 `cargo test --locked`。界面测试先运行 `pnpm dev`，再从仓库根目录运行 `node tests/desktop-ui.test.cjs`。该测试使用隔离浏览器和模拟 IPC，不写实际平台。

原生验收需要在 `src-tauri` 运行 `cargo build --locked --features smoke-test`，保持前端开发服务开启，然后从仓库根目录运行 `node tests/desktop-native.test.cjs`。它只连接本地模拟 WOS / SA / 重复数据 / 学者页面并使用独立临时工作目录，验证连续三条零结果后第四篇仍检索、完整记录导出、WebView2 实际文件保存、跨 SA 复用、Rust 身份核验、SQLite 和来源 Excel；另外执行一次明确选择的重复合并，并跑通两个独立作者原因的核对与 SA 完成。作者编辑场景按完整工号读取身份和表单，分别保存通讯作者、共同第一作者，回读完整字段和 SA，并拒绝旧准备的重复保存。生产安装包不启用 `smoke-test`。

零匹配场景另外验证纠正题名后已有、预置推送后检查点各关联一次，实时原因逐项处理、完整工号认领与两条 SA 独立完成。故意遗漏模拟页面关联后的本地完成记录，再重开 SQLite 并执行启动恢复例程，结果未知禁止重发，只读核验后恢复原推送阶段与载荷。本场景没有执行上传/导入/推送，也没有重启应用进程/WebView2。

另有完整导入场景，从已核验 TXT 和实际前端零条查询开始，上传、导入、按 PPT 五项设置推送各一次，再查前端实际条目、关联、按完整工号认领、逐原因核对到 SA 已处理。导入和推送提交后分别重开 SQLite、执行启动恢复，结果未知拒绝重复提交，再只读回读批次文献和完成计数。实际页面收到的文件、机构/说明、五项设置保存为 `native-import-receipts.json`，执行来源与完整批次回读保存在 SQLite 和来源 Excel。全部为本地合成页面；没有真实平台写入或完整进程重启；上传原窗口保留时的未知恢复另有故障注入验收。

推送选项从页面实际字段、可见标签和对应值读取，不固定使用优先级合并/新增编号。选项缺失、歧义、含义变化、隐藏或禁用时停止。运行 `node tests/workflow.test.cjs` 可复现 47 个隔离场景；旧扩展的 20 个桥接场景也已回归通过。

完整进程重启验收：保持 `pnpm dev` 开启，并使用上述 `smoke-test` 二进制，从仓库根目录运行 `node tests/desktop-restart.test.cjs`。只连接本地模拟服务器；它在服务器收到导入/推送后强制结束该测试应用和其 WebView2 子进程，再用同一隔离工作目录启动新进程。检查原意图/原文件保留、未知阶段拒绝重发、被改动的归档不能核验、完整批次回读与重复回读无写入。上传/导入/推送各一次；另一上传样本在原窗口丢失且无批次时保持未知并拒绝上传/导入。测试根目录只接受固定目录下的 UUID，生产安装包没有该测试入口。认领、合并、字段修改和真实认证会话的完整进程重启尚未纳入此测试；下载队列已由下面的独立场景验证。

## 当前验收边界

原生下载回执恢复：运行 `node tests/desktop-download-restart.test.cjs`，同样保持开发服务并使用 `smoke-test` 二进制。实际下载完成、回执保存后而归档前强制结束应用和浏览器，重启不打开 WOS 即恢复原文件并继续原队列；另一真实 HTTP 下载在请求已接收但响应不完整时强制结束，重启保持待核验，不重新检索/导出。四个独立应用进程、无平台写入。完成回执绑定准确原任务、来源、唯一路径、原字节哈希、大小及时间；恢复时重新解析完整记录，检查输入与身份，任务/论文/归档证据和回执消费原子保存。未知、缺失、被改动或输入已变化的文件不自动采纳；可在来源页核验后读取本地单篇 TXT。来源 Excel 包含未完成和失败回执的实际状态，不能据此宣称材料已就绪。新增 10 项核心测试覆盖这些边界和事务回滚。

下载队列完整进程恢复：运行 `node tests/desktop-queue-restart.test.cjs`，仍需开发服务和上述测试二进制。测试在前三条零结果后、第四条搜索中终止自己的应用及 WebView2，再用同一隔离目录启动新进程；检查原范围和位置、已记录结果、变更任务和新增行隔离、缓存复用、关闭浏览器后的通道暂停与续接。另一个范围在搜索中请求暂停，保存后终止进程，验证重启继续原范围。4 个独立应用进程、每个工作目录 1 份实际 TXT，没有上传/导入/推送。`node tests/desktop-queue-ui.test.cjs` 验证真实界面的原队列入口、切换负责人不替换范围、通道错误、取消确认和 960 像素布局；该界面测试使用模拟 IPC。

已验证前端交互、确认取消、主题、侧栏、分页、排序、最小窗口布局与切换任务时的身份隔离，以及重复候选选择、逐原因独立表单、对应未知结果回读入口和旧版迁移预览；Rust 的 87 项测试覆盖身份冲突、多篇文件拒绝、恢复与防重复写入、原子保存、论文共享与版本歧义、合并历史、独立待处理原因、实际角色/工号回读、来源引用、编号精度与模板格式、作者编辑完整字段保留、本库查询、原名单零匹配转实时唯一及关联恢复。新增 7 项旧数据迁移测试，使用实际 SQLite、Excel 与 TXT 检查旧键兼容、只读源数据、完整日志和归档复制、幂等、冲突回滚、历史输入不同、非法文件、旧操作及名单外导入防重复，以及旧 SA 完成只读回读。另有 7 项新名单版本测试覆盖逐字段回读、候选替换、事务回滚、历史保留和跨版本重复上传拒绝。首次 SA 与本库字段、修正后的字段及逐项结论保存在 SQLite 和来源报告。

原生模拟下载、重复合并、多原因处理及作者角色保存闭环已通过。作者角色场景分别保存通讯作者和共同第一作者，两个控件各提交一次，并检查完整元数据、SA 角色及最终处理备注；旧的编辑准备不能重复提交。未知保存只读恢复已通过隔离适配器测试；实际平台与原生重启恢复场景仍待验收。

本库前端检索依据公开 `advancedSearch/searchModal` 组件与 `searchItemList` 成功事件实现，实际路由为 `/advancedSearch`（普通路径），不是后台的 `#/...`。运行 `node tests/desktop-library.test.cjs` 可复现 14 个隔离场景；原生模拟确认三种查询完整保存、无依据不能判缺失、已有候选不能新增、实际 ID 必须明确选择。没有执行真实站点查询或写入验收；现场字段缺失或含义改变时程序拒绝推断缺失。

真实 WOS 机构登录与下载、真实后台首条导入 / 推送 / 认领闭环仍待现场验收。学者别名适配器依据平台公开页面组件实现，12 个隔离场景通过，尚未在真实登录后保存验收；运行 `node tests/desktop-scholar.test.cjs` 可复现。重复条目适配器同样依据公开组件实现，17 个隔离场景及实际 Tauri 模拟链路通过；运行 `node tests/desktop-duplicate.test.cjs` 可复现，真实平台合并未现场验收。作者编辑适配器依据实际 `itemModelEdit` 组件实现；运行 `node tests/desktop-metadata.test.cjs` 可复现 18 个隔离场景，覆盖可见复选框、完整字段、未保存草稿、表单校验、未知结果和只读恢复。作者/单位顺序和其他角色标记的自动调整，以及非 WOS 数据库直接导出尚未完成。其他实际模板可注册并调用 API 准备材料。整体验收目标尚未全部完成。
