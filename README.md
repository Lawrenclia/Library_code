# 机构知识库工作台

基于 **Tauri 2、Rust、TypeScript/Vue 3 和 SQLite** 的 Windows 桌面工具。以 `list.xlsx` 为输入，按机构知识库 SA 匹配结果处理论文，统一管理数据库来源、原始下载、API AI 分类、实际 Excel 模板、导入推送、作者认领及来源报告。

当前源码版本：**0.2.0**。本次按用户要求仅编译打包，不运行测试、不启动应用、不操作真实网站。代码接通与页面实际兼容性分别记录，详情见 [实现核对](docs/TAURI_COMPLETION_AUDIT_0_2_0.md) 和 [交付记录](docs/TAURI_ACCEPTANCE_STATUS.md)。

## 下载 Windows 安装包

打开 [Windows EXE 工作流](https://github.com/Lawrenclia/Library_code/actions/workflows/windows-exe.yml)，选择成功运行，在 **Artifacts** 下载 `Windows-EXE-版本-提交` 压缩包，解压后使用其中的 `机构知识库工作台_版本_x64-setup.exe`。

也可以点击 **Run workflow**，保持工作流分支和 `source_ref` 为 `main`，在 GitHub 编译当前源码，无需本机安装 Rust 或 Node.js。产物同时包含 `build-info.json` 和 `SHA256SUMS.txt`，用于核对版本、源码、实际大小和哈希；默认保留 30 天。详细步骤见 [GitHub 编译说明](docs/GITHUB_ACTIONS_BUILD.md)。

应用使用 Windows WebView2 内置浏览器；安装时可补装 WebView2。新版 EXE 不依赖 Python 或 Chrome 扩展。

## 第一次使用

1. 在“名单”导入 `list.xlsx`，选择负责人。**只考虑 Excel 物理 A 列为空的行**；“已处理”、其他文字、数字等非空值全部跳过。SA ID、工号和长平台编号请保存为文本，以免 Excel 丢失精度。
2. 在“模型与设置”查看实际工作目录，配置 HTTPS API 基础地址、模型及密钥。密钥保存在 Windows 系统凭据中，来源报告不导出密钥。
3. 打开数据库和机构库工作页，在内置窗口完成机构认证、登录和验证。后台需具备 PPT 规定的学生馆员权限。
4. 在“来源”优先获取数据库原始文件。其他渠道先保存真实入口及允许的下载域名；页面默认识别不适用时，在“渠道流程”保存实际控件定位条件。单篇获取和按负责人批量获取使用同一套来源校验。
5. 下载完成后，明确选择本篇记录，核对题名、标识符、交大归属和重要字段，填写来源与核对依据。多篇文件不能直接作为单篇提交文件。
6. 原始导出不可用时，保存当前详情的完整来源，注册平台实际模板，再调用 API AI 分类、填写有依据的字段。缺项会保留在草稿和报告中。
7. 按匹配数处理本库查询、逐项核验或重复合并。需要补充时，分别确认上传、导入、推送，再关联实际平台条目、认领作者并回读 SA。
8. 导出“材料与来源”Excel，保留分类、渠道、来源文件、完整依据、字段引用、队列、批次及失败原因。

具体操作和异常恢复见 [0.2.0 使用与自测说明](docs/TAURI_TESTING_0_2_0.md)。配置 API 会产生实际调用费用；只有主动启动 AI 操作才发出请求。

## 按 PPT 处理任务

规则依据 [原始 PPT 整体逻辑](docs/TAURI_REBUILD_GOAL.md)，流程为：

`原名单 → 来源与身份核对 → 本库查询/差异核验 → 原始导出或模板 → 上传 → 导入 → 推送 → 关联/认领 → SA 回读 → 来源报告`

| 匹配条目数 | 处理方式                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 0          | 区分非交大、SA 题名有误但本库已有、本库确实缺失、未查询到文献。只有交大成果且本库确实缺失时进入补充。 |
| 1          | 按每个待处理原因独立核对通讯作者、第一作者、单位、认领和 DOI/WOS 身份，必要时修改实际字段并回读。     |
| 2 及以上   | 明确选择主条目和被合并条目，核对完整字段及保留内容，合并回读后继续 SA 原因核验。                      |

非交大需要真实归属依据；题名有误时使用来源中的正确题名查本库；未查询到保存具体检索范围和备注，**不设置已处理**。网络、登录、页面识别错误不能当作零结果。

WOS 按 PPT 使用核心合集、核对目标记录、导出制表符 TXT 和完整记录。平台导入机构为“上海交通大学”，说明为 `SA补充-<sa_lzk表ID>`。上传、导入、推送分别保存回执；推送使用 PPT 的五项设置：

| 设置           | 值                                                                 |
| -------------- | ------------------------------------------------------------------ |
| 是否查重       | 是                                                                 |
| 查重方式       | 唯一标识 +（期刊、发表时间、页码、卷、期、题名相似度）+ 题名相似度 |
| 重复条目元数据 | 根据优先级合并                                                     |
| 不存在的条目   | 新增                                                               |
| 是否本校成果   | 是                                                                 |

控件实际文字或含义不符时停止等待核对，不按选项序号猜选。论文归属、作者身份、主条目及最终处理均需明确核对；AI 建议不会自动完成 SA。

## 来源渠道和下载方式

**成果类型与导入渠道独立保存。** 成果类型不局限于期刊论文、会议论文、科技论文、著作章节；可注册其他真实模板。

| 来源/渠道                           | 获取方式                                                           | 机构库提交材料                                 |
| ----------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| WOS TXT                             | 专用检索、目标身份核验、完整记录导出、原生下载完成回执             | 核验过的单篇完整记录 TXT                       |
| WOS Excel                           | 通用来源驱动或内置窗口原始下载                                     | 与实际 Excel 入口契约一致的文件                |
| CNKI                                | 官方检索和题录获取；内置窗口原始下载；通用流程可补充原导出步骤     | 符合入口的 Excel/TXT；网页 XLS 可审计另存 XLSX |
| CSCD、CSSCI、万方、EI、VIP、IncoPat | 共用检索、完整结果核对、详情来源和原始导出驱动，可保存各站控件步骤 | 各入口实际接受的 TXT、CSV 或 Excel             |
| Scopus、其他来源                    | 共用来源驱动、原始文件、RIS 和详情字段接入                         | 供 AI 与实际平台模板整理；不虚构专用导入按钮   |
| DOI / Crossref                      | 按 DOI 读取登记元数据，归档完整 JSON                               | 来源依据，不直接当作原始导入文件               |
| 数据导入 / 平台模板                 | 注册真实 Excel 文件，按列说明、必填、枚举及格式准备                | 实际平台模板材料                               |

通用流程优先核对完整结果范围并选出唯一精确题名；结果不完整或有歧义时要求进入已核对的单篇详情。默认控件识别与保存的定位条件都按当前页面检查，未适配的页面不会默认点击第一篇。渠道步骤只保存选择器、实际文字和点击/选择/勾选动作，不执行用户填写的脚本。

所有来源窗口下载直接保存到工作台目录。只有原生下载完成、实际文件和哈希一致才记为成功；打开详情、点击导出或保存路径存在都不能替代下载回执。支持原始 Excel/CSV/TXT、RIS、CNKI EndNote/RefWorks 标记题录和明确的文本记录选择。Excel 另存保留原件、完整单元格及转换回执；不能完整保留的文件停止转换。

网页详情与 CNKI 题录响应保留原始内容、重复字段、未知字段、URL 和哈希，供 AI/模板整理。**派生 RIS、API JSON 或页面文本不是数据库原始上传文件**。重要字段缺失会列出，不补造 DOI、页码、单位或作者角色。

各数据库页面、访问权限和实际导出格式可能不同；通用驱动接通不表示各站现场兼容性已经通过验收。

## 暂停、恢复和卡顿处理

- WOS 和其他来源队列冻结负责人、论文顺序、原名单和逐篇结果，**没有“连续三条失败结束”规则**。明确无记录等逐篇失败继续后续论文。
- 登录、Cloudflare 524、通道超时、页面断开或结果未知暂停原队列，保留位置和文件；恢复页面后继续原范围。524 表示来源服务器超时，不能证明该论文无记录。
- 批量来源任务完成一篇后关闭该队列新建的窗口，保留登录资料目录；发生阻塞时保留当前工作页，避免为整张名单累积浏览器窗口。
- 退出或重启后不会自动重发未确认的原始导出或平台写入。先回读原会话、原文件或原批次；多份原生下载需要明确选择。
- 原来源导出确实未完成时，关闭原会话所有窗口，核对实际下载记录并填写取消原因，才可取消原导出检查点。文件和历史记录保留；已经完成的文件应先核验采纳。
- 上传、导入、推送、合并、认领等结果未知时，使用对应“回读/核验上次结果”。冻结的原载荷不会被新的 AI 建议或表单值覆盖。
- 名单关键字段变化时保留旧版本，显示待核验差异；新名单非空 A 列任务不能借旧队列绕过当前范围。

## 文件保存位置

在“模型与设置”查看真实绝对路径并点击“打开工作目录”。默认使用本机 Tauri 应用数据目录，由安装用户决定；不会自动使用系统浏览器的 `Downloads`。

| 工作目录下的位置                       | 内容                                       |
| -------------------------------------- | ------------------------------------------ |
| `inputs/`                              | 原名单归档与输入哈希                       |
| `downloads/`、`downloads/sources/`     | 内置浏览器实际下载及来源文件               |
| `artifacts/`                           | 身份核验后的 WOS 原文件归档                |
| `source-responses/`                    | 数据库/API 完整原始响应与页面来源          |
| `source-originals/`、`source-resaves/` | Excel 原件、另存文件和转换回执             |
| `templates/`                           | 已注册的真实平台模板                       |
| `materials/products/<版本哈希>/`       | 单篇材料、缺项及字段来源审计               |
| `materials/batches/<批次ID>/`          | 批量材料与来源报告                         |
| SQLite 和浏览器资料目录                | 任务、原意图、队列、检查点、回执及登录状态 |

导出的 Excel 可自行选择保存位置，包含任务与来源、原始依据、AI 字段来源、渠道获取记录及完整历史队列。长 JSON/来源按顺序分段保存，保留完整内容，不静默截断。

## 本地开发与编译

需要 Windows Rust MSVC 工具链、Visual Studio C++ Build Tools、Node.js 22、pnpm 和 WebView2。

```powershell
cd desktop
pnpm install --frozen-lockfile
pnpm desktop
```

只编译安装包：

```powershell
cd desktop
pnpm exec tauri build --bundles nsis -- --locked
```

产物位于 `desktop/src-tauri/target/release/bundle/nsis/`；如设置了 `CARGO_TARGET_DIR`，位于对应目录的 `release/bundle/nsis/`。生产编译自动执行 Vue/TypeScript 前端构建，默认不会运行测试或启动程序。

## 项目结构

| 目录                                | 责任                                          |
| ----------------------------------- | --------------------------------------------- |
| `desktop/src/`                      | Vue 3 / TypeScript 工作台及 shadcn-vue 界面   |
| `desktop/src-tauri/src/`            | 原生窗口、命令权限、调度、平台服务及 API      |
| `desktop/src-tauri/browser/`        | 数据库和机构库页面驱动                        |
| `desktop/core/src/`                 | Rust 业务规则、SQLite、证据、模板、文件及恢复 |
| `desktop/src-tauri/capabilities/`   | 本地/远程窗口权限边界                         |
| `extension/`                        | 部分共用页面驱动；其余扩展界面为旧版          |
| `docs/`                             | PPT 逻辑、架构、版本记录和使用说明            |
| `.github/workflows/windows-exe.yml` | GitHub Windows EXE 编译与产物归档             |

SQLite 负责业务状态；页面驱动只提交观察到的结果，由 Rust 验证。远程来源页只有受会话、来源和命令令牌约束的结果回传权限，不能直接修改设置、读取密钥或调用任意本地文件操作。架构详情见 [FRAMEWORK.md](docs/FRAMEWORK.md)。

根目录 Python 工具和旧 Chrome 扩展保留历史实现，新版日常使用与编译均从 `desktop/` 进入。旧 README 可在 Git 历史中查看。界面组件来源和 MIT 许可见 [第三方声明](desktop/THIRD_PARTY_NOTICES.md)。
