# Tauri + Rust 重构总体逻辑与 Goal

编制日期：2026-10-08。

依据：`D:\Library\2026-09-21-机构知识库数据比对工作(1).pptx`。已核对全部 10 页文字、备注和关键操作截图。第 10 页为空白。下面使用 PPT 文件中的页序，封面为第 1 页。

本文是后续实现规范。本次交付为流程和目标定义，不表示新架构已经实现或真实平台已经验收。

## 1. 总体 Goal

使用 Tauri 2 + Rust 重构机构知识库 SA 比对助手。以 list.xlsx 为任务输入，依据 PPT 按匹配条目数分流，统一完成证据获取、成果归属核验、机构库检索、元数据下载或模板准备、导入推送、作者认领与处理结果记录。每个结论和文件均可追溯到原始 SA 记录、来源证据及具体执行步骤。任务可暂停、恢复和逐条核验，结果不明的写入先回读确认，避免重复导入或推送。

重构完成的标准是实际业务闭环和可恢复性，不以新窗口显示、搜索成功或按钮点击成功作为完成依据。

## 2. 依据边界

### PPT 明确规定的业务

- 第 2 页：统一认证登录机构库前端、后台，后台需要学生馆员权限。
- 第 3 页：进入 SA 数据比对结果，处理“待处理”记录。
- 第 4 页：匹配数 1，按待处理原因核对本库信息或认领。
- 第 5 页：匹配数 2，检查重复数据，选择主条目并合并。
- 第 6 页：匹配数 0，分为非交大、题名等提交错误、本库缺失、未查询到文献四种情况。
- 第 7 页：通过图书馆数据库入口访问 WOS，选择核心合集，输入标题检索，导出制表符分隔文件与完整记录。
- 第 8 页：选择 WOS 数据导入（Txt），所属机构为上海交通大学，导入说明为 `SA补充-<sa_lzk表ID>`，上传成功后导入，导入成功后按指定选项推送。
- 第 9 页：学者管理按工号检索，在别名窗口新增别名并保存。

### 用户此前明确增加的需求

- 从 list.xlsx 读取名单，分类、填写等需要 AI 时调用 API。
- 先考虑数据库原始 Excel/TXT 导出，再考虑模板填写；模板不局限于已提供的四个文件。
- 分类同时记录成果类型和导入渠道，并输出来源表。
- 逐篇检索完整范围，取消“连续 3 条 WOS 失败就结束”。
- 内置浏览器，下载直接保存到助手管理的目录。
- 将功能整合到统一桌面工作台，并采用 Tauri + Rust 重整架构。

PPT 第 6 页对零匹配的分流，细化了“零匹配需要提交”的一般说法：只有交大成果且本库确实缺失时进入补充导入。

### 工程实现规则

本文中的数据库结构、状态名称、错误代码、恢复机制、界面结构、AI 返回契约及实施顺序属于工程设计。PPT 没有规定这些技术细节。PPT 没有给出 Scopus、CSCD 等其他数据库的完整操作教程，也没有规定通用模板的全部必填列，不能将 WOS 步骤直接套用到其他渠道。

## 3. 整体业务流程

### 3.1 任务输入和平台准备

1. 导入 list.xlsx，校验负责人、sa_lzk 表 ID、题名、匹配条目数等任务字段，保存导入版本与原表行号。
2. 原表字段缺失或同一 SA ID 出现冲突内容时，展示问题并等待修正，不自行推断任务身份。
3. 同一论文允许关联多条 SA 记录。可以复用已经核验的元数据文件，各条 SA 记录的认领、处理状态和结果映射分别保存。
4. 打开机构库前端、后台与数据库访问窗口，用户完成统一认证。分别显示页面加载、认证访问、机构库权限、当前任务运行状态。
5. 按用户选择的负责人和处理范围生成任务队列。Excel 的数字 2 跳过标记与平台匹配条目数 2 是两个独立字段。
6. 执行前回读对应 SA 记录，核对 SA ID、关键任务字段及当前平台状态，避免按旧名单操作已变化的数据。

### 3.2 匹配数为 1：核对现有条目（PPT 第 4 页）

| 待处理原因 | 证据与判断 | 后续处理 |
|---|---|---|
| 通讯作者、第一作者、交大是否第一单位不一致 | 阅读原文或可靠原始来源，确认具体作者角色与署名顺序 | SA 正确则修改本库对应字段；本库正确则保留其值，设置已处理并按核对结论备注 |
| 作者不一致且未认领 | 对照工号、学者身份和文献作者 | 认领对应成果，回读认领结果 |
| DOI 和 WOS ID 都不一致 | 判断是否同一篇，使用 DOI 对应来源核对哪个正确 | 确认同一篇后按 PPT 设置已处理；不同篇进入人工核验，不能直接套用同篇结论 |

一条记录可能有多个待处理原因，必须逐项完成后才能进入最终处理步骤。PPT 没有允许仅凭名字相似度判断通讯作者、第一作者或第一单位。

### 3.3 匹配数为 2：重复条目处理（PPT 第 5 页）

1. 进入“数据任务池 → 重复数据管理”。
2. 按题名检索，检查匹配记录是否确为同一成果。
3. 确认主条目，列出将合并的其他条目与保留字段。
4. 将其他条目合并至主条目，回读合并结果和主条目 ID。
5. 回到 SA 比对任务核对最新匹配情况，继续处理剩余原因。

截图中的题名相似度 99.00 是示例页面值，不定义为通用自动合并阈值。工程上将匹配数大于 2 的任务同样送入重复核验队列；这属于对 PPT 的扩展。

### 3.4 匹配数为 0：先判断原因（PPT 第 6 页）

| 分支 | 需要确认的事实 | 后续处理 |
|---|---|---|
| A. 非交大成果 | 来源证据确认该文献不属于交大 | 设置已处理，备注“非交大” |
| B. SA 题名等信息有误 | 外部数据库找到正确文献，并确认属于交大 | 用正确题名在机构库前端检索，找到平台唯一号，再核对现有条目；不能直接上传 |
| C. 交大成果，本库没有 | 数据库记录或可靠材料确认文献身份、交大归属，机构库前端核查无对应条目 | 获取元数据，准备导入；导入与推送成功后回到 SA 任务继续处理 |
| D. 未查询到文献 | 保存实际检索范围、查询词、时间和结果，仍无法定位文献 | 备注“未查询到该文献”，平台不设置已处理 |

数据库零结果只说明本次查询未定位文献，不能单独证明“未发表”或“非交大”。归属或身份证据不足时进入待核验。网络失败、登录失败、页面识别失败与数据库零结果必须分开记录。

### 3.5 元数据获取与模板准备

WOS 按 PPT 第 7 页执行：

1. 图书馆首页 → 数据库 → WOS → 数据库首页。
2. 确认选择 Web of Science 核心合集。
3. 输入标题检索。DOI/WOS ID 辅助检索、题名修正和当前 Smart Search/Fielded Search 页面适配属于工程增强，必须保存实际查询方式。
4. 核对目标记录身份与交大署名。多条结果需明确目标，不能默认第一条。
5. 对目标记录导出“制表符分隔文件”，内容选择“完整记录”。
6. 接收本次任务的原生下载事件，保存到专用目录，确认文件实际完成下载，再解析其字段与身份。
7. 保存文件哈希、数据库来源、记录链接、真实题名、标识符、下载时间和关联 SA ID。

其他数据库优先使用该平台实际支持的原始导出。各渠道分别配置格式、页面操作与校验规则，不把平台不支持的格式强行转换为该平台的原始导出。PPT 备注提到 CNKI 元数据全选导出 Excel，需打开另存后再导入；备注没有完整说明具体页面流程，需要单独验证。

用户要求的成果类型和导入渠道分别存储。已知渠道包括通用模板、WOS Excel/TXT、CSCD TXT、CSSCI TXT、CNKI Excel/TXT、万方、EI CSV/Excel、VIP Excel、IncoPat Excel，Scopus 等渠道按可用导出接口注册；这是用户需求与工程扩展，不是 PPT 全部都有的教程。

无法取得可用原始导出时，选择平台实际提供的模板。读取模板列、说明、必填要求、枚举和格式约束，覆盖已提供的期刊论文、会议论文、科技论文、著作章节及后续新增模板。

AI 仅依据输入和已取得的来源返回字段值、证据引用、置信情况与缺项。不编造 DOI、页码、作者角色、署名或数据库收录。必填信息缺失则标记待补充，保留已完成字段。AI 返回结构化结果，由本地程序验证并写入 Excel。

### 3.6 WOS 上传、导入、推送（PPT 第 8 页）

1. 进入“数据管理 → 数据导入与批次管理”。
2. 选择“WOS 数据导入（Txt）”。
3. 所属机构设为“上海交通大学”。
4. 导入说明使用正文指定值 `SA补充-<sa_lzk表ID>`。上传截图中的 `WOS202603-01` 是示例字段内容，不能替代正文规则。
5. 上传核验通过的文件，观察上传成功标志；此时仅为上传完成。
6. 点击导入，等待并回读该批次导入结果；确认文件、批次说明与任务身份一致。
7. 导入成功后进入该批次的推送设置，逐项核对下表。

| 推送字段 | 第 8 页截图指定值 |
|---|---|
| 是否查重 | 是 |
| 查重方式 | 唯一标识 +（期刊 & 发表时间 & 页码 & 卷 & 期 & 题名相似度）+ 题名相似度 |
| 重复条目元数据 | 根据优先级合并 |
| 不存在的条目 | 新增 |
| 是否本校成果 | 是 |

程序匹配选项的实际含义和文字，不硬编码截图中的控件位置或未经核验的选项序号。指定选项缺失或含义改变时等待核验，不自动替换为相近选项。

8. 执行推送，回读推送结果，记录实际产生或合并后的平台唯一号。
9. 使用题名、标识符和平台唯一号回读机构库记录，回到 SA 比对任务完成核对、认领及必要备注。

只有已确认属于交大的文献才可使用“是否本校成果：是”。推送完成不直接等同于 SA 处理完成。

### 3.7 作者认领与别名（PPT 第 4、9 页）

1. 认领对象以学者身份和工号核对，不能仅以英文姓名缩写自动确定人员。
2. 需要新增别名时进入“研究单元/用户管理 → 学者管理”。
3. 按工号检索，打开对应学者的“别名”，点击新增，填写实际存在于来源中的名字并保存。
4. 回读别名与认领关系，确认操作生效，再继续 SA 处理。

新增别名是必要时的分支，不是每篇文献都必须执行的步骤。截图中的姓名、工号和别名是示例，不作为业务固定配置。

## 4. 状态与错误模型

### 分开保存的状态

- 任务输入：原表版本、SA ID、负责人、匹配数、处理原因、行号映射。
- 业务分支：现有条目核对、重复核验、非交大、纠正题名后查库、缺失补充、未查询到、证据待核验。
- 来源检索：待检索、检索中、明确结果、零结果、歧义、检索受阻。
- 文件：未取得、下载中、已下载、文件校验通过、身份待核验、材料不完整、提交材料就绪。
- 平台执行：待上传、上传中、上传成功、导入中、导入成功、推送中、推送成功、认领完成、SA 回读完成。
- 任务运行：排队、运行、暂停、等待人工核验、操作结果待确认、完成。

AI 分类完成、文件下载完成、上传成功、导入成功、推送成功和平台已处理是不同事实，分别记录。

### 结构化错误及恢复

| 错误类型 | 调度行为 |
|---|---|
| `NO_RESULT` | 保存本次检索结果，继续其他来源或下一篇 |
| `AMBIGUOUS_RESULT` / `IDENTITY_CONFLICT` | 当前条目待核验，继续不依赖它的任务 |
| `INCOMPLETE_METADATA` / `FILE_INVALID` | 当前材料待修复，不能进入上传 |
| `AUTH_REQUIRED` / `BROWSER_DISCONNECTED` | 暂停对应执行通道，保留剩余队列，恢复后继续 |
| `PAGE_UNSUPPORTED` | 展示当前步骤和诊断；该通道待适配或人工处理 |
| `REMOTE_RESULT_UNKNOWN` | 上传、导入、推送、合并、认领等结果不明时先回读平台，不能直接重发写入 |

使用错误代码驱动调度，提示文案仅供显示。普通逐篇失败不会触发连续三条停止。页面操作超时按操作是否已发出、是否有副作用分类，不能统一当作零结果。

任务恢复使用已保存的执行记录、原始文件、哈希和平台批次/条目 ID。已核验的文件复用，已确认的写入跳过，未确认的写入先回读。暂停作用于当前运行任务，不使用某个界面页的分类停止标志。

## 5. Tauri + Rust 模块边界

| 模块 | 职责 |
|---|---|
| Vue 3 + TypeScript 界面 | 任务列表、详情、证据、进度、可执行的下一步与人工核验 |
| Rust 业务核心 | PPT 分流规则、字段核验、完成条件、结构化错误 |
| Rust 调度器 | 任务队列、通道并发控制、暂停恢复、事件分发 |
| 浏览器执行接口 | 统一会话状态、导航、脚本执行、页面结果和下载事件；Tauri WebView 为主要执行端，外部扩展适配器可接入同一接口 |
| 数据库来源适配器 | WOS、Scopus、CNKI 等各自的检索、结果识别、导出和来源解析 |
| 机构库适配器 | 前端检索、SA 读取、条目编辑、上传导入推送、重复合并、认领与别名 |
| AI 服务 | API 配置、请求、结构化分类/补全和证据引用；不直接决定平台完成状态 |
| 文件与模板服务 | 原始文件归档、哈希、Excel 输入输出、模板注册与必填校验 |
| SQLite 存储 | 论文、SA 任务、证据、材料、批次、执行尝试、核验结论与操作事件 |

整个应用只有一套业务分流和一套任务状态。浏览器端负责执行页面动作，界面负责显示与收集确认。第三方数据库网页与桌面本地界面分属独立权限范围，网页结果通过受约束的执行接口返回。

论文身份与 SA 任务身份分开：一篇论文可以关联多条 SA 记录及多个来源。查重合并必须有可核验依据。Excel 是输入输出载体，运行中状态存入 SQLite。全文件哈希保留作快照审计，正常备注/来源输出不再要求重建全部任务索引。

## 7. 验收条件

1. PPT 第 4—9 页的每个业务分支，都有输入、判断依据、操作步骤、结果回读和完成条件。
2. 零匹配的“非交大”“本库已有”“本库缺失”“未查询到”四个场景分别走正确路径；只有本库缺失的交大成果进入导入准备。
3. 匹配数 1 的多原因逐项核对；相同论文但标识符不同的处理有证据，不能只比较字符串。
4. 匹配数 2 的合并保存主条目、被合并条目与回读结果，不能把 Excel 数字 2 的跳过标记误当作匹配数。
5. 真实登录 WOS 后至少完成一篇目标论文的核心合集检索、完整记录制表符 TXT 下载、文件解析、身份与来源记录。模拟测试和仅有下载按钮截图不能替代此验收。
6. 原始导出优先；模板按实际字段约束填写。关键必填内容缺失进入待补充，AI 每个补填结论能追溯到来源证据。
7. 导入说明准确关联 SA ID；只有上传成功才点击导入，只有导入成功才进入推送，五项推送设置与 PPT 一致。
8. 推送成功后能找到机构库条目并继续 SA 核对/认领。下载或推送完成不能提前标记 SA 已处理。“未查询到该文献”不设置平台已处理。
9. 暂停或重启可恢复队列；连续三篇普通失败后仍执行后续论文。真实通道不可用时记录剩余项为未执行。
10. 上传、导入、推送、合并、认领的结果未知时先回读，确认前不自动重复写入。
