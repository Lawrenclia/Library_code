## 修复的实际问题

1. **来源选择残留：** 更换表头、工作表或分页后，旧记录选择及列映射可能继续保留。现在重新载入时清理选择，结构改变时重新识别列；原始冻结来源复用仍保留原选择。
2. **提交核对命令权限缺失：** 主窗口已有 `review_submission` 调用和后端实现，但构建命令与能力清单遗漏。已补齐生成权限、主窗口授权，并检查两端命令一致性。
3. **备注恢复约束过宽：** 原备注验证曾直接将阶段还原用于检查，可能接受已变化的任务。现在仅允许正常原阶段，或具有完全一致原意图和人工核对的 Unknown 恢复；Completed 和缺少原意图的恢复拒绝。
4. **CNKI 安全验证被当作加载等待：** `/verify/home` 的滑块页及检索页拼图浮层没有密码输入框。现在专用/共用驱动明确返回 `AUTH_REQUIRED`，原生导航在验证跳转时停止等待。已完成验证后移到屏幕上方的旧浮层不会误报为仍在验证。

首次核心测试为 256 通过、6 失败。其中 5 项是旧测试期望不再符合当前渠道、来源报告、旧材料键约束及名单换版行为，按当前契约修正；其余为上述备注阶段约束问题。界面初次有 4 个失败：旧文案期望与来源选择状态均已修复。下载队列暂停恢复测试修正了“暂停一定发生在 HTTP 发出之后”的错误时序假设，仍严格检查原队列恢复、请求范围和文件不重复，未修改生产队列逻辑。初始失败日志保留。
