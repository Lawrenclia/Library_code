# 0.1.11 名单换版后的原批次恢复

补齐 CNKI、其他数据库原始导出和模板材料的跨名单版本检查点，不再只依靠原生 WOS 归档保留旧批次。

- 已有提交材料或批次时，名单文件、行号等输入快照变化也进入版本核验，避免悄悄改写原提交范围。
- 核对新名单与实际 SA 后，保留原文件、原意图、原始来源快照、历史版本及旧批次；原文件字节仍需核对。
- 先回读原上传、导入或推送结果，不能把旧成功阶段直接用于新名单，也不会重新上传。
- 回读通过后，原材料仍锁定；继续导入或推送须重新核验新名单的身份、交大署名和本库缺失。新名单的题名、DOI 或 WOS 身份冲突时保留待核验版本及原批次，不创建新的提交。
- 再次更换名单仍使用最初的来源快照和原文件。不能借助新材料、修改渠道或丢失历史证据绕过检查。平台已处理的新名单仍保留原批次用于报告。
- 已有原批次的任务不能改成“未查询到”。

新增跨版本重启、再次换版、回读、原材料变更、载荷及历史证据变化、论文身份冲突的回归场景源码。按用户要求只编译打包，没有运行测试、安装启动或真实网站操作。编译成功不证明暂停恢复和防重复提交已现场验收。

自测建议：先用一篇真实 CNKI 单篇原文件或实际模板完成上传，然后调整名单负责人或行号并重新导入。核对 SA 接受新版本后，检查原批次与原文件仍显示；先回读，再重新保存核验，继续导入。期间不应重新上传。重启及第二次换名单重复上述步骤。若原文件或论文身份不同，应停止并保留原操作记录。

其他业务步骤见 [0.1.9 自测说明](TAURI_TESTING_0_1_9.md)。除 WOS 外的数据库检索、选篇及导出仍在内置浏览器人工操作，各渠道实际表单尚待自测。
