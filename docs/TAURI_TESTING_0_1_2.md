# 机构知识库工作台 0.1.2 自测说明

该版本打包当前 Tauri 2 + Rust + SQLite 开发源码，供用户自行测试。只进行生成安装包所必需的前端生产构建、Rust release 编译和 NSIS 打包；未启用 `smoke-test`，不运行测试套件，不安装或启动程序，不操作真实数据库或机构库。

## 本次包含的后续代码

- 上传、导入及推送的完整回执核验，结果不明时先回读，不自动重发。
- 名单物理行号、重复身份检查、新名单版本的旧批次回读与迁移冲突预览。
- WOS 逐篇查询记录、范围绑定、失败继续及同篇文件复用的来源核对。
- 原始 Excel、CSV、显式表格 TXT 的整表候选定位，保留全部候选和冲突，由用户明确选择。
- Crossref DOI 来源、Scopus CSV 来源登记、完整来源及材料交接资料包。
- 未查询到文献时的备注准备、复制交接与只读回读，保持 SA 未处理。

以上仅说明源码已打包，不证明各项实际业务已经通过。其他数据库的自动检索、自动导出和自动机构库导入仍未实现；Scopus CSV 是原始来源，不表示机构库存在对应导入选项。自动提交驱动目前仅 WOS TXT。

## 安装与首次使用

1. 自行退出正在运行的旧工作台，再运行 `机构知识库工作台_0.1.2_x64-setup.exe`。助手没有替你关闭旧程序、安装或迁移实际数据。
2. 打开后确认左侧底部显示 **v0.1.2 测试版**。Git 更新不会更新已安装程序，仍显示 v0.1.1 时没有运行本次新版本。
3. 在工作台导入实际 `list.xlsx`，选择负责人，先使用少量记录自行核对。原行号、SA ID、匹配数、跳过标记和工号分别保存。
4. 在“流程与连接”打开需要的内置页面，自行登录数据库与机构库；窗口可见不表示学生馆员权限已通过。

## 处理流程

匹配 0 条时先取得论文来源，核对身份与交大归属，再以正确题名和标识符查机构库。只有交大成果且确认本库缺失才进入补充导入。非交大、有现存条目、未查询到和证据不足走各自核验路径，不能将全部零匹配任务直接上传。

WOS 按核心合集检索，选择准确的论文记录，导出制表符分隔文件与完整记录。下载结果须出现实际文件路径；只有搜索结果、下载按钮或网络零结果都不能当作文件已取得。逐篇普通失败继续，登录或页面通道故障保留未执行项。

其他来源在单篇“来源”页配置实际入口与下载域名，在内置窗口自行检索和导出。也可选择已下载的原始文件；选择实际表头、题名和标识符列后，可以按名单定位整表候选。必须核对候选和冲突再明确选择，不默认采用第一条。文件所有字段和原字节保留，来源绑定不会自动确认交大归属。

原始导出优先。无法取得可用原始格式时，在“模板与材料”注册平台实际模板，再调用已配置的 AI API 分类或补填。缺少必填内容、无来源引用或身份不明时保留待补充；AI 分类不决定平台成功。

WOS TXT 的平台步骤分别是选择材料、确认机构及 `SA补充-<SA ID>`、上传、导入、核对五项推送设置、推送、回读条目和 SA、按工号认领及必要别名、逐项解决差异后完成 SA。不要把文件已下载、上传成功或推送成功当作 SA 已处理。

匹配 1 条逐项核对全部差异；匹配 2 条及以上先核实重复和主条目，合并后回读，再处理剩余问题。未知操作结果使用对应“核验/回读”入口，不能重复点击写入。原上传窗口丢失且查不到可靠批次时仍保持结果未知。

“未查询到该文献”可准备独立备注并复制。只在平台有**单独保存备注且不改变状态**的入口手动保存后回读，不使用“设置已处理”替代；真实独立编辑入口尚未验收。

## 文件与问题反馈

以工作台“打开工作目录”显示的实际路径为准：WOS 下载在 `downloads`，其他来源下载在 `downloads/sources`，绑定原文件在 `source-files`，材料在 `materials/products`，运行记录在 `workspace.sqlite3`。本次打包没有读取或改变你的真实任务数据库、API 密钥和浏览器登录状态。

保留出现问题的 SA ID、具体步骤、报错文字、实际文件路径和导出的来源 Excel 报告。提交材料资料包可保留原文件、来源、缺项和阶段，材料准备或导出不会自动执行平台操作。

安装包对应提交、实际大小及 SHA256 见交付目录的 `版本信息.json`。完整业务要求见 [重构目标](TAURI_REBUILD_GOAL.md)，逐项验收范围见 [交付状态](TAURI_ACCEPTANCE_STATUS.md)。
