# 0.2.2：App 内 CNKI 只读检查与修复

日期：2026-10-12。承接 [0.2.1 测试记录](TEST_RESULTS_0_2_1.md)，用户确认 App 内验证码已完成后，继续检查同一个 Tauri/WebView2 来源窗口。没有使用聊天侧边浏览器，也没有上传、导入、推送、合并或认领真实数据，没有调用真实 AI API。

## 现场观察

App 窗口为“原始来源 · cnki · SA readonly-cnki-20261012”。验证后显示真实 CNKI 检索页和“上海交通大学”机构访问；默认字段是“主题”，题名为本地只读测试记录的公开论文题名。

结果区明确显示：**“抱歉，暂无数据，请稍后重试。”** 随后通过页面可见下拉框改为“篇名”，点击一次搜索，仍显示相同提示。没有可核对的记录列表，不能选择论文、进入目标详情或确认原始导出通过。此提示说明本次来源页面未正常返回结果，不等于“论文未收录”；没有据此猜测服务异常的具体原因。

后续电脑锁屏，按 Computer Use 操作规范停止全部页面输入。锁屏截图单独保存为 `runtime/validation-0.2.2-20261012/desktop-locked.png`，不能作为 CNKI 页面截图。先前未锁屏时的截图及可见页面文字在本次工具记录中；本地仅保存不含会话令牌的观察摘要。

## 修复

- 按名单题名检索改用篇名字段 `korder=TI`，完整题名以一个编码后的 `kw` 值传递。结果仍需完整范围及唯一精确题名核对；不自动放宽条件，也不选择首条。此前使用 `SU` 的原结果检查点继续可读。
- CNKI 专用和共用来源驱动识别上述临时重试提示，及时返回 `SOURCE_SERVICE_UNAVAILABLE`，保留窗口并等待后续明确继续，避免消耗完整结果等待时间。不会返回零条记录，也不会自动再次提交。

参数映射参考现有 [jasminum CNKI 检索实现](https://github.com/l0o0/jasminum/blob/main/src/modules/services/cnki.ts)，同时根据本次 App 可见字段核对。新的自动篇名 URL 仍需恢复桌面后现场核对，不能把离线构造测试当作真实页面通过。
