# 0.1.10 原操作恢复与材料锁定

保留 0.1.9 的按渠道提交及独立备注流程，修复上传后更换材料和从当前字段重建回读载荷的问题。

- 上传或原批次已存在后，前后端禁止更换提交材料、重新保存其他材料核验；查看和导出来源记录仍可进行。
- 导入、推送和恢复读取 SQLite 中已保存的原始导入意图。新的未发送尝试不会覆盖此前成功上传的原意图。
- 尚未确认的尝试优先使用其原载荷。已核验上传重启后，也从原意图恢复，不需要重新读取模板审计文件来生成一份新候选。
- 原操作保存的提交包仍有历史证据且原字节、名单及来源事实一致时，可以核验原包；不会因为旧版本允许更换材料而悄悄采用最新选择。归档字节变化、原 SA 不符或来源版本变化仍拒绝采纳。
- 兼容已有 WOS 旧版批次检查点；没有保存原意图的新版非 WOS 材料不会从当前表单重新生成恢复请求。

新增四个核心回归场景源码，覆盖重启后的原意图、未发送的新尝试、上传后的材料锁定、保留原提交包及原字节篡改。按用户要求本轮只编译打包，未执行测试、启动应用或操作真实网站。真实暂停恢复和防重复提交尚待自测，不能把编译成功记作业务验收通过。

安装后重新导入名单，先测试一篇原始导出：上传成功后应锁定材料；重新打开程序后先回读上传，再提交导入，期间不应重新发出文件上传。完整业务步骤沿用 [0.1.9 自测说明](TAURI_TESTING_0_1_9.md)。
