# 0.1.12 使用说明

本版继续补齐代码，再由用户统一自测。只编译打包，不运行测试、不安装启动，也不操作真实业务网站。

## CNKI 获取流程

1. 选择当前名单中的零匹配论文，在来源渠道选择 CNKI。
2. 点击“自动检索并获取 CNKI 题录”。工作台使用本篇专属内置窗口和保存的 CNKI 会话，按名单题名打开检索页。
3. 先等待原生浏览器确认页面加载，再等待结果表稳定。只有能确认全部结果已呈现、且只有一条精确题名匹配时才进入详情。浏览器与 Rust 分别核对查询、结果数量、实际链接和任务版本。
4. 详情页加载后，从当前页面实际提供的同源 GetExport 入口获取完整 EndNote/RefWorks 题录。保存原始响应、详情来源、检索结果、导出编号和全部未知/重复字段；缺项逐项列出。
5. 在预览中选择本篇记录并填写绑定依据，完成身份和交大署名核对，再用于 AI 分类或实际模板填表。题录响应不冒充网站原始下载，也不直接当作已通过渠道格式核验的上传文件。

若需登录或验证码，在内置窗口完成后重新点击自动获取即可。多页结果、同名论文或无法确认完整结果数量时，程序不选首条；请在网页缩小检索，或打开确认后的详情页，再点“获取当前详情页题录”。服务器超时、网页加载超时和真实空结果分别提示；均不自动改写 SA 状态。

若网页支持直接导出 Excel/TXT，优先使用网页原始导出。下载由应用接收，保存到当前工作目录的 `downloads/sources`，可在“下载记录”中选择记录。CNKI Excel 另存保留原文件，提交原导出仍须核对整个文件只含本篇及必要字段。

CNKI 题录响应另存到 `source-responses`，带来源的题录 TXT 保存到 `downloads/sources`；这些保存路径会显示在题录预览。尚未绑定的 TXT 可通过选择本地来源文件重新打开，绑定后的完整来源随任务持久保存。

## 延续已有流程

名单只处理物理 A 列为空的记录。WOS 保留完整记录 TXT 下载、524 通道暂停和原位置恢复；普通论文检索失败不触发“三条停止”。其他渠道可配置实际网站入口，接收原始文件、选择记录、保留全部字段，调用 API 分类/填实际模板，再按渠道的运行时表单约束进行上传、导入、推送与回读。

上传后的原文件、原提交意图和批次沿用 0.1.11 的恢复逻辑：未知结果先回读，换名单先核对旧批次，不能换文件重新上传。上传、导入和推送由明确的对应动作触发，CNKI 自动获取本身不执行这些操作。

## 当前边界

CNKI 自动获取按公开结果表/详情页协议实现，真实登录、验证码及页面版本兼容性尚未自测。机构代理入口只接入原始网页下载；不根据官方域名协议操作代理页面。其他数据库的专用自动检索、选篇、导出驱动没有在本版新增，继续使用可配置浏览器原始下载和本地来源路径。

本地和 GitHub 安装包的生产编译成功仅证明能构建。真实 WOS、CNKI、机构库表单及全部业务分支是否符合现场页面，需要安装后验证。新增选篇范围回归用例为源码，本轮未执行。

错误反馈请保留版本、SA ID、渠道、具体按钮、完整报错，以及来源窗口当前页面。结果未知的上传/导入/推送应先回读，不要重发。
