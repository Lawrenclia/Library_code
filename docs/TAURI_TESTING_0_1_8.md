# 0.1.8 来源格式与 RIS 题录

本版补充来源整理能力，保留 0.1.7 的 WOS 站点故障暂停、当前目标保护及物理 A 列空白输入范围规则。

## 新增行为

- 渠道 `formats` 继续表示登记的平台格式；新增 `source_formats` 表示本地整理可读取的格式。接收 RIS 来源不会给平台增加 RIS 上传能力。
- 文件选择和内置来源浏览器原生下载接收共用来源格式配置，可以接收 `.ris` 文件。以 `.txt` 保存且首个非空行为 `TY` 的 RIS 同样自动识别。
- RIS 要求完整 `TY ... ER` 记录边界；缺失结束标记、记录外额外内容、题名缺失、同篇题名/DOI 冲突均拒绝采纳。不用第一条记录替代目标论文。
- 保留每条记录的全部标记、重复作者、未知字段、多行摘要和原始完整记录；整个原始文件按字节归档并保存哈希。题名和 DOI 单列用于现有的全表候选查找与人工绑定。
- RIS 经当前文件、任务、字段和哈希重新核验后进入 AI 来源和报告；它用于模板准备，不会直接成为机构库原始上传材料。
- 常见 Excel/CSV 表头可以预填题名、DOI、WOS 列；多个同义列同时存在时不自动决定。用户仍选择具体记录并核对依据。

## 用户自行检查的顺序

1. 导入第一列为空的名单。在一条任务的原始来源区域选择实际渠道，选择真实导出的 RIS 文件；核对显示的是表格题录而不是文本碎片。
2. 检查原始完整记录、作者、摘要及其他字段；使用“定位本篇”检查全部记录，不仅是当前预览页。明确选择目标并填写绑定依据。
3. 针对实际平台模板调用 AI，检查字段引用及缺项，再准备模板和来源报告。RIS 获取不代表交大归属、机构库缺失或平台已处理。
4. 对缺少 ER 的不完整文件，应看到拒绝读取；不能据此记录数据库零结果。身份冲突应保留待核验。
5. 内置来源浏览器需要配置真实入口和下载域名，用户完成登录并点击实际导出。这里只接收真实原生下载事件，没有增加其他数据库自动检索或自动点击导出。

本版按用户授权仅修改和编译打包。新增解析与接入回归用例源码，未执行测试、安装启动或真实网站操作。CNKI及其他非 WOS TXT 渠道的机构库自动上传、导入和推送仍未实现。

## 格式依据

Scopus 官方支持说明列出 CSV、RIS、BibTeX 的可导出字段，并明确不同格式字段集合不同：[Scopus 元数据导出字段](https://www.elsevier.support/scopus/answer/what-fields-are-used-when-exporting-documents-from-scopus)。RIS 字段与边界参考公开的 [Zotero RIS 读取器](https://github.com/zotero/translators/blob/master/RIS.js)，本版保留原始字段，没有复制其实现，也没有将通用格式读取称为各数据库专用导出适配。
