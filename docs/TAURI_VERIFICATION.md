### 导入与推送批次完整回读：尚未验证、未打包（2026-10-10）

原 Rust 恢复入口依赖页面返回 `verified` 与批次状态，完整文献核对主要由页面适配器完成。现在恢复上传、导入或推送后，本地核心也核对 WOS 来源、精确 SA 说明、文本批次/模型 ID、单篇总数、零失败、导入与推送实际计数，以及唯一文献的题名、WOS ID 和原 DOI；推送恢复不会凭未推送批次解除未知状态。已记录批次 ID/模型/来源/说明/总数绑定原检查点，临时上传对象不冒充批次。

浏览器回读后再次读取原归档，确认完整 Candidate 和哈希与原执行载荷一致，才保存阶段和完整回执。写入点击本身仍不视为导入或推送成功，SA 完成仍走独立核验。新增场景仅写入代码，未执行测试、编译、平台回读或打包；0.1.1 测试包不包含本节修改。

### AI 事实与本地操作审计分离：尚未验证、未打包（2026-10-10）

原事实筛选使用操作类型排除清单，新增加的日志类型可能漏入 AI。现在明确允许当前名单、核验后的 WOS/外部导出/DOI 元数据，以及有来源和非空正文的人工原文依据；历史名单不能伪装为当前 `roster_input`。当前名单仍由程序只生成原题名、DOI、WOS ID，旧的 `manual` 原文类别兼容保留。下载回执、检索结果日志、机构库查询与修改回读、合并/推送结果和任务版本历史不作为论文事实发送至模型。

这些记录完整留在本地和来源报告，不删除历史，也不改变平台核验规则。AI 返回的分类及每个字段引用同样检查事实类别，操作回执不能充当补写作者、单位等字段的依据。已有 AI 建议若引用了这些日志或其已记录来源哈希变化，必须重新分类后才能填写模板。补写的场景覆盖日志不进入 API 输入、未知新日志默认排除、当前名单重新生成、日志完整报告及非法来源引用；尚未执行测试、构建或打包，0.1.1 测试包保持不变。

统一 AI 与模板的 WOS 事实读取入口：读取实际单篇原文件，检查普通文件类型、大小、完整 Candidate/字段/哈希一致性及与名单的已知标识符是否冲突。历史 `metadata` 摘录保留在报告，但只有与当前原文件及来源一致的最新完整字段摘录可作为分类、模板事实；没有当前原文件的历史摘录不进入 AI。仅有身份线索不足仍不会自动确认论文身份或归属。

### DOI 登记元数据补查：尚未验证、未打包（2026-10-10）

新增本地工作台的 Crossref DOI 来源查询入口，按当前名单的有效 DOI 构造固定 HTTPS 提供方地址，禁止重定向、限定读取时长和完整响应大小，不自动重试。优先读取已有且原字节仍一致的当前来源；重新查询只更新元数据事实，不更改论文身份、交大归属、机构库状态或平台阶段。

Crossref JSON 是模板事实来源，不注册为机构库原始导入渠道，也不转成 WOS TXT。实现依据 [Crossref 官方 API 文档](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)。四个本地核心场景仅写入代码，未运行；未执行类型检查、编译、打包或真实 API 查询。0.1.1 安装包继续固定对应 `7a85082`，不包含本节后续修改。
