# 机构知识库工作台 0.1.1 测试版

这是供用户自行测试的 Windows 版本，底层采用 Tauri 2、Rust、SQLite。名单、任务版本、原始证据、文件、材料和平台操作分别保存；搜索成功不会记为下载成功，材料保存不会记为导入或 SA 完成。

## 使用顺序

1. 退出正在运行的旧工作台，运行 `机构知识库工作台_0.1.1_x64-setup.exe`。同一工作目录只允许一个实例，旧版仍在运行时新版不会接管任务。
2. 确认左侧底部显示 `v0.1.1 测试版`，在“任务工作台”导入实际 `list.xlsx`。第一次测试先选择少量论文和对应负责人。
3. 在“流程与连接”打开需要的内置页面，自行完成数据库和机构库登录。窗口打开不代表认证或学生馆员权限已通过。
4. 对匹配 0 条的任务，先取得真实来源，再核对论文身份、交大归属和本库是否已有；只有确属交大且本库缺失才进入补充导入。
5. WOS 使用核心合集、准确论文记录、制表符分隔文件和完整记录。按任务执行下载；结果里应出现实际文件路径和文件版本，不能只有搜索结果。
6. 其他数据库在单篇“来源”页配置实际入口和下载域名，在内置来源窗口自行检索和导出。成功下载后选择文件中的准确论文记录，映射题名和标识符，填写绑定依据并确认。也可以选择已下载的原始 Excel / CSV / TXT。
7. 同一论文有多条 SA 时，可在“来源”查找同一 DOI / WOS ID 的已有文件，明确选择后为当前 SA 单独确认。原文件和来源快照保留，认领和处理状态各自独立。
8. 原始导出能用时优先保留原文件。“模板与材料”可注册实际模板；需要 AI 分类或填写时，先在“模型与设置”配置 API。必填内容缺失、引用无来源或有歧义时保留待核对，不编造内容。
9. 在本篇“平台操作”选择提交材料。机构、`SA补充-<SA ID>`、文件和来源版本一并保存。上传、导入、推送、认领、SA 完成各有独立步骤和回读；待核对材料不能自动上传。
10. 测试完导出来源报告。任务、原文证据、下载结果、材料版本和提交选择保留在报告中。暂停后可继续原队列；结果未知的写入先核验，不直接重复提交。

匹配 1 条按差异原因逐项核对已有条目；匹配 2 条及以上先核实重复候选和主条目，合并后回读，再处理剩余差异。合并本身不结束 SA。

## 文件在哪里

点击工作台的“打开工作目录”，以界面显示的实际目录为准。

| 子目录 | 内容 |
| --- | --- |
| `downloads` | WOS 内置下载请求及原始文件 |
| `downloads/sources` | 其他数据库内置窗口保存的原始文件 |
| `source-files` | 绑定来源时保留的完整原字节文件 |
| `source-reuse` | 跨 SA 复用时冻结的来源快照 |
| `materials/products` | 原格式材料、生成模板和完整来源记录 |
| `workspace.sqlite3` | 任务、队列、来源证据及本篇提交准备记录 |

每条记录也显示自己的实际文件路径。未收到完整下载回执时不会宣称成功；关闭窗口或退出留下的文件保留为未确认，不自动采用。

## 本版边界

- 自动上传驱动目前接通 WOS TXT。其他渠道可下载、读取和整理原格式材料，自动导入仍待接通。
- 其他数据库的自动检索、自动选择记录、自动点击导出尚未实现，需在内置来源窗口操作。
- 不把 AI 分类当作论文身份、交大归属或平台成功的证明。
- 本次仅为生成可安装版本进行前端构建和正式编译，不启用模拟功能；没有执行测试套件、安装启动、真实网站验收或实际平台提交。

遇到问题时，保留任务的 SA ID、当前步骤、报错文字和来源报告，便于定位。完整业务规范见 [重构目标](TAURI_REBUILD_GOAL.md)。
